## Defects

1. **Blocking — AC6 fixture cannot fail as written.** Component 11, lines 427–431, copies a non-allowlisted slug using `shouldCopy` and then checks the copied tree. The filter removes that slug, so `assertNoLeak` finds nothing and the command succeeds. Keep the production filter and post-copy alarm, but add a distinct CI source-tree rule that fails on any forbidden slug; test the post-copy alarm by deliberately planting a leak after filtering. Make both failure modes required in task 010.
2. **Blocking — moved EndCard has an unresolved, branded QR import.** Components 5–7 and 14, lines 250–254, 285, 337–340, 655–656, omit `waitlist-qr.ts` because the inventory correctly leaves its Ptah-specific output in Ptah. `EndCard.tsx` imports that file, while the proposed QR executor writes a PNG elsewhere. Specify one working generic contract: derive the QR URL and display text from `brand.config.ts`, emit the exact data EndCard consumes, and ensure the generated smoke studio typechecks and renders without the excluded Ptah module. Also port the named `@xterm/headless` dependency and JSON output for `tui-frames` (lines 286, 310); the current contract would fail at runtime.
3. **Blocking — first publish may omit approved deliverables.** Order of work, lines 748–755, says the new kit/promo task is not needed by 013; current roadmap 013 depends only on 010 and 011. This permits publishing before `doctor` (007, AC3), the preset (012), the kit/promo executors and generators (new task), and possibly the editor (008). These are in the proposed public package and `kit-build` is needed for Ptah's AC10 migration. Add release dependencies on every required deliverable and make the AC2/AC4/AC8 real render smoke a required pre-publish proof rather than an optional weekly workflow (lines 622–625). If editor is intentionally deferred from the first release, reserve that scope choice for the user.
4. **Serious — generated frame contract does not meet the copied assembler.** Component 13, lines 489–490, describes a `.scene` root and `data-start`/`data-duration`; source `assemble.mjs:29–72` requires a `<template>`, an `fNN` id, matching composition id, dimensions, frame start/duration, and a seam on later frames. Specify the full output shape and unit-test the generated frame through `assemble` and `check` for AC8.
5. **Serious — `keepExistingVersions` permits an unpinned generated workspace.** `init` at lines 303–315 warns and retains mismatched versions when the flag is set; the Ptah migration expressly uses it at line 761. Hard rule 3 requires pinned versions in executors and generators. Remove this bypass for engine packages, or fail with an actionable conflict and require an explicit user migration step. Keep all `@remotion/*` at exactly 4.0.484.
6. **Serious — a named marketplace capability is omitted without approval.** Component 12, line 461, and D12, line 860, ship no MCP server entry although `docs/decisions.md` defines a marketplace with skills, agents **and MCP servers**. The editor generator's local `.mcp.json` setup may be a sound implementation, but it changes the marketplace contract. Mark this as a proposed omission and request the user's choice between a portable marketplace entry and generator-only setup. `## Proposed Removals` at lines 876–881 currently says none.
7. **Moderate — several contracts defer essential behavior beyond this approval gate.** `outro` and `tui-frames` options are “flags mirror the script” (lines 284–286); the marketplace schema and install command remain assumptions A7/A8 (lines 462–464); `createNodes` callback shape is A13 (lines 590–602). Resolve source-checkable details now where possible, and state explicit fallback tests for environment-dependent details. The inventory mapping's “remaining studio rows (≈63)” and task 005 reconciliation (lines 656, 664) should become an exact file list or mechanical coverage check before approval.
8. **Moderate — engine isolation is enforced only by a test, contrary to the requested module-boundary enforcement.** Lines 132–152 and D13 line 861 give Nx tags to whole projects while both engines occupy one plugin project; the engine separation is only a unit test. Add an import-boundary lint rule covering internal engine paths (including dynamic imports and `.mjs` scripts), and retain the test as a backstop. The shared spawn/path modules may remain engine-neutral.
9. **Moderate — kit runtime neutralisation is underspecified.** Lines 494, 659 say to strip `ptah-ui` identifiers, but `runtime.js` also has a Ptah-specific MCP tool icon branch and `data-ptah-part` selector. Specify replacements/removal for those behaviors, then test the generated kit output and published tarball for branded strings. This is required for the public-template rule, not a mere rename.

2. **What happens at every failure boundary?** Mostly fail-closed: git failures in both guards exit 1 with a message; missing `npx-cli.js` throws; `npx --no-install` cannot silently fetch a newer `nx`; spawn failures in the registry setup propagate and `teardown()` runs in the same catch (`start-local-registry.ts:77-80`). 5. **Unspecified cases?** Native `Revert "..."` subjects (finding 8) and PR/push event duplication (finding 1) are cases the requirements left open and the implementation resolves in a way worth a second look.

## Findings

1. **Moderate — `.github/workflows/ci.yml:3-11`** — `on: [push, pull_request]` with `concurrency.group: CI-${{ github.ref }}`. A push to a PR branch and its `pull_request` event carry different refs (`refs/heads/task/...` vs `refs/pull/N/merge`), so they land in different concurrency groups and never cancel each other: every commit on a PR branch runs the full 3-OS matrix (including both Verdaccio e2e legs) twice. *Fix:* filter `push` to `branches: [main]`, or key concurrency on `${{ github.head_ref || github.ref }}` (or the commit SHA).
2. **Moderate — `tools/scripts/start-local-registry.ts:57-60`** — TOCTOU on port 4873. The preflight pings the port, then the script spawns verdaccio; if a *different* process binds 4873 inside that window and answers `/-ping` before our child's `EADDRINUSE` death is observed, `waitForRegistry` (:41-51) returns "ready" against the foreign registry and `nx release publish` (:75) publishes `@hive-academy/nx-video@0.0.0-e2e` to it. Low likelihood on isolated CI runners, real on a shared dev machine. *Fix:* after the first successful ping, assert `registryProcess.exitCode === null` after a short stabilization delay, or have verdaccio bind a script-chosen free port and report it, and ping only after our own child has bound.
3. **Moderate — `packages/nx-video/eslint.config.mjs:3-7,84`** — `FORBIDDEN_SPAWN_STRINGS` (`tools/eslint/engine-zones.mjs:87`) is consumed only by the isolation spec; no ESLint rule enforces it. The approved plan requires "a lint `no-restricted-syntax` literal selector duplicates the second" assertion (`TASK_2026_002_dcb6/implementation-plan.md:178`). Also the substring list misses `spawn(Sync)("npx"` (double quotes) and `shell:true` (no space). The plan's promised two independent layers exist for pin literals but not for the hard-rule-5 spawn strings. *Fix:* add `no-restricted-syntax` selectors for `npx.cmd`, bare `'npx'` string literals and `shell: true` object properties to the zone blocks, and broaden the spec's substrings accordingly.
4. **Moderate — `packages/nx-video/src/engine-isolation.spec.ts:39-41`** — `matchesGlob` only understands a trailing `/**`; the `PIN_LITERAL_ALLOWED_FILES` entry `src/generators/**/files/**` (`tools/eslint/engine-zones.mjs:85`) has a mid-path `**` and can never match (it is compared as a literal `src/generators/**/files/` prefix). Today it is masked because `isExcluded` (:44) drops `src/generators/*/files/` files before scanning, so the allowlist is dead code that *looks* like it covers generator templates; if the exclusion is ever relaxed, templates with pinned versions fail the backstop with no allow path. *Fix:* make `matchesGlob` handle `**` segments (or use a real glob matcher), or delete the dead entry and rely on `isExcluded` alone, documented.
5. **Minor — `tools/scripts/start-local-registry.ts:66`** — `--location=none` is passed to `nx run nx-video-source:local-registry`, but it is neither an nx CLI flag nor an option of `@nx/js:verdaccio`; verified that Nx silently drops it (`nx run nx-video-source:no-media --location=none` succeeds). It documents decision row 10's intent without enforcing anything — the real guarantee is `NPM_CONFIG_USERCONFIG` (:64). *Fix:* remove the vestigial arg (or comment why it is forwarded), so nobody later assumes an npm-config write is being suppressed by it.
6. **Moderate — `tools/eslint/engine-zones.mjs:12-22`** — the zone table's `allowed` column is documentation only; both enforcement layers implement the `forbidden` deny-list. Consequence: a bare npm-package import of the *other* engine is invisible — remotion-zone code doing `import 'hyperframes'` (or hyperframes-zone code importing `remotion`/`@remotion/*`) matches no `**/<segment>/**` path pattern and `prohibitedPackage` returns false for those zones (`engine-isolation.spec.ts:73-82`). That is a hard-rule-4 cross-engine dependency neither layer catches from task 005 onward. *Fix:* add `forbiddenPackages: ['hyperframes']` to the remotion zone and `['remotion', '@remotion/*']` to the hyperframes zone, and enforce `forbiddenPackages` in both the spec and `packageRestrictions` in the ESLint config.
7. **Minor — `.github/workflows/ci.yml:63-65`** — the `commits` job sets `cache: npm` but never runs `npm ci`; the restore and post-job save are pure overhead against the shared cache quota. *Fix:* drop `cache: npm` from that job.
8. **Minor — `tools/scripts/check-commits.mjs:5`** — native `git revert` subjects (`Revert "feat: ..."`) are rejected; only `revert:` / `revert(scope):` pass. A maintainer reverting with git defaults fails the PR-only check and must rewrite the subject. Confirm this strictness is intended; if native reverts should pass, special-case a `Revert "` prefix (they are single-parent and otherwise unambiguous).
9. **Minor — `tools/scripts/start-local-registry.ts:43`** — `waitForRegistry` tests only `exitCode !== null`; a child that dies via *signal* keeps `exitCode === null`, so readiness spins the full 60 s and reports "did not become ready", hiding the real cause. `stop-local-registry.ts:6` checks both `exitCode` and `signalCode` — be consistent. *Fix:* also bail when `signalCode !== null`.
10. **Minor — `tools/scripts/start-local-registry.ts:13-25` and `e2e/nx-video-e2e/src/test-utils.ts:15-27`** — the Windows-safe `npxCli()` helper (hard rule 5's core) exists twice and can drift; the two copies already diverge in nothing today only by luck of copy-paste. The architecture notes explicitly allow a shared Windows-safe spawn helper as engine-neutral code. *Fix:* extract one module (e.g. `tools/scripts/npx-cli.ts`) and import it from both.
11. **Minor — `tools/scripts/stop-local-registry.ts:9`** — if the registry spawn failed, `child.pid` is `undefined` and `String(child.pid)` sends `taskkill /pid undefined /T /F`, which fails silently (the spawnSync result is discarded); the `exit` promise then never fires and teardown burns its full 10 s timeout. *Fix:* guard `if (!child.pid)` and fall through to `child.kill`.
12. **Minor — `packages/nx-video/src/index.ts:1`** — `src/index.ts` is in no zone (the plan's table lists none for it either), so a *side-effectful* cross-engine import in the package barrel is invisible to both the lint and the isolation spec. Re-exports are the intended design, but a real import would be unflagged. *Fix:* give the barrel a minimal zone (forbid `src/remotion/**` and `src/hyperframes/**` targets for non-`export ... from` imports), or accept and document the hole.

Non-findings, checked deliberately: `no-media.mjs` fails closed on git errors (`:50-51`), handles `.MP4`-style case via `extname().toLowerCase()` (:30), matches `large-files.allow` by exact path and rejects malformed lines (:18-21); the `@nx/enforce-module-boundaries` exception is limited to exactly the three consumers of `engine-zones.mjs` (`packages/nx-video/eslint.config.mjs:92-94`); `${{ }}` is only ever expanded into `env:`, never inline into `run:`; the e2e matrix matches D5; no `^`/`~` ranges in any `package.json`; the temp `.npmrc` is mode 0600 and outside the repo, and nothing writes the user's `~/.npmrc`; the isolation spec is a real backstop, not a tautology — its scanner is self-tested against a synthetic tree (`engine-isolation.spec.ts:151-171`) proving static, dynamic and `require` detection plus `..` normalization. The only TODO-style marker in the diff is the PR template's `TASK_YYYY_NNN_xxxx`, which is its intended placeholder.
